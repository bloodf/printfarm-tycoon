in [`TRACKER.md`](TRACKER.md). Every milestone ends at a **review gate** where you, the
director, approve it before the next one starts.*

> so you can review each workstream on its own.

## 2. Decisions log

| # | Decision | Reason |
|---|---|---|
| D1 | **Web only, single-player.** No Steam, no desktop build, no multiplayer | Director decision |
| D2 | **Printers modelled on real machines** (Creality Ender-3 V3 SE, Prusa MK4, Bambu Lab P1S), at real dimensions and with real design details | Authenticity; the 3D-printing community will recognise them |
| D3 | In-game names are **parody brands** ("Kreality", "Prusla", "Bamboo Lab"), set in one data file | Avoids trademark problems. A one-line change if you want real names |
| D4 | **First-person, hands-on** (like Supermarket Simulator), with the in-game laptop for orders and email | Core fantasy: you physically run the farm |
| D5 | **Assets are generated by code**: Blender 5 (Python, headless) builds every model → GLB; Python builds PBR textures and synthesises sounds | No internet asset stores are available here; this way every asset can be rebuilt, reviewed and versioned |
| D6 | Renderer: **Three.js r187 on WebGL2** + post-processing (SSAO, bloom, AgX tone mapping, SMAA). WebGPU is re-evaluated at M4 | The post-processing ecosystem and browser support are mature on WebGL2; WebGPU support in R3F/postprocessing is still uneven |
| D7 | Game logic is a **pure TypeScript simulation**, separate from rendering | Testable, saveable, balanceable |
| D9 | **Two control schemes**: first-person (WASD) and **Point & Click** (mouse-only orbit camera), switchable at any time | Director request at M1 gate: the game must be playable just by pointing and clicking |
| D10 | **Realism through baked lighting**: Cycles-baked indirect lightmaps for the room, baked AO for every asset; direct light stays real-time | Removes the "plastic/CG" look without losing dynamic shadows |
| D11 | **No avatar**: the game is pure Point & Click; first-person mode removed (supersedes D4/D9) | Director: "we will never see our character" |
| D12 | **Garage capacity by size class** (M/L/XL slots) | Real machines have very different footprints (Prusa XL ≫ K1) |
| D8 | Deliverable after each milestone: **source zip without `node_modules` and `dist`** | Director requirement |

## 4. Asset pipeline (how an asset gets into the game)

```
brief (docs/specs/ART.md) → Blender script (tools/blender/assets/*.py)
  → build: GLB + Cycles preview render (docs/qa/assets/*.png)
  → review against the reference sheet (dimensions, silhouette, details)
  → in-game check (screenshot in the garage under game lighting)
  → tracker: ✅
```

Every printer GLB follows a **rig contract** (named nodes such as `Bed`, `GantryZ`,
`CarriageX`, `Toolhead`, `PrintOrigin`, `Screen`, `Door`). The game animates those nodes,
so models can be improved without touching code.

## 5b. M1 gate review: what to check

Built and QA'd (see [`qa/README.md`](qa/README.md) and [`TRACKER.md`](TRACKER.md)). Please review:

1. **Look:** `docs/qa/beauty/*.jpg`: do the printers read as Ender / MK4 / P1S? Is the garage believable?
2. **Feel:** play a day (`npm run dev` on a machine with a GPU, High preset): movement, prompts, hold actions, packing.
3. **UI:** the laptop apps, HUD, menus and settings: anything unclear or missing?
4. **Audio:** listen (nobody has yet): printer steppers, fans, UI clicks, radio music.
5. **Scope for M2:** reorder or cut items from the M2 row above.

Your decision: ✅ approve → M2 starts · 🔁 changes → they go into the tracker as M1.1 tasks first.

## 6. Process rules (how we keep control)

1. **Plan first, then build.** New features go into the plan and tracker before any code.
2. **Small tasks** in the tracker, each with an owner workstream, a status and evidence.
3. **Evidence or it didn't happen:** renders/screenshots in `docs/qa/`, tests green, build green.
4. **Gate review** at the end of each milestone. The next milestone waits for your approval.
5. **Zip delivery** at every gate: `printfarm-tycoon-<milestone>.zip`, without `node_modules` and `dist`.
6. **Data-driven content** (`src/data/`): balance changes need no code changes.

## 7. Risks

| Risk | Mitigation |
|---|---|
| Code-generated models can look "CAD-like" | Bevels on every edge, real dimensions, many small details (screws, cables, decals), PBR textures, good lighting and SSAO |
| Synthesised audio can sound artificial | Layered synthesis (noise + resonances + envelopes), loudness normalisation, sounds stay subtle in the mix. Can be replaced with recorded samples later: same file names |
| The browser GPU budget | Per-asset triangle budgets, shared materials, a quality preset in the settings |
| Scope | The vertical slice has to be *good* before growth features. Features get cut, not quality |
